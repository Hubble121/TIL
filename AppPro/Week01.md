# 앱프로그래밍 1주차 배운 내용 정리

## 1. 앱프로그래밍 학습 방향
- **학습 목표** : AI와 함께 앱을 만들되, 개발자가 구현 내용과 동작 원리를 직접 설명할 수 있도록 학습
- **기본 과정** : 의도 → 구현 → 검증 → 성찰
- 개념을 학습한 뒤 직접 적용하고, 실행 결과를 확인해 기록하는 과정이 중요

## 2. Flutter와 멀티플랫폼 개발
- **Flutter** : 하나의 코드베이스로 여러 플랫폼의 앱을 개발할 수 있는 프레임워크
- **Dart** : Flutter 앱 개발에 사용하는 프로그래밍 언어
- **지원 플랫폼** : Android, iOS, Web, Desktop 등
- 코드 재사용, 빠른 피드백, Widget 기반의 명확한 UI 구조가 주요 특징

## 3. Flutter를 사용하는 이유
- **Hot Reload** : 개발 도중 수정 사항을 빠르게 화면에 반영
- **Widget** : UI를 작은 구성 요소로 조합하는 단위
- 모바일부터 웹까지 하나의 개발 경험으로 연결 가능
- 화면 구성뿐 아니라 구조와 테스트를 함께 학습하기에 적합

## 4. 코드 작성과 소프트웨어 엔지니어링
- **프로그래밍** : 코드를 작성하여 기능을 구현하는 활동
- **엔지니어링** : 설계·개발·테스트·유지보수까지 제품의 전체 생애주기를 고려하는 활동
- 빠르게 동작하는 코드를 만드는 것뿐 아니라 지속적으로 변경할 수 있는 구조를 만드는 것이 중요

## 5. AI Agent와 개발자의 역할
- **AI Agent** : 주어진 목표를 수행하기 위해 도구와 정보를 활용하여 작업하는 AI 시스템
- AI는 코드 작성과 아이디어 탐색을 도울 수 있지만, 요구사항 판단과 결과 검증은 개발자의 책임
- AI가 제안한 코드도 동작·보안·범위·설명 가능성을 확인해야 함

## 6. 컨텍스트 엔지니어링
- **컨텍스트(Context)** : AI가 작업을 판단할 때 참고하는 목표, 코드, 문서, 제약과 작업 정보
- **컨텍스트 엔지니어링** : 필요한 정보를 선택하고 작업 결과에 따라 갱신하는 과정
- 단순히 긴 프롬프트를 전달하기보다 관련 있는 자료와 검증 기준을 제공하는 것이 중요
- 요구사항, 현재 코드, 사용 가능한 도구, 완료 기준을 명확히 구분

## 7. 도구 선택과 결과 검증
- AI나 개발 도구를 사용할 때는 **목적, 입력, 출력, 권한, 부작용**을 확인
- 실행하지 않은 코드를 실행에 성공했다고 기록하지 않음
- 문제가 발생하면 실제 로그와 재현 방법을 기준으로 해결
- 구현 결과뿐 아니라 왜 그 방법을 선택했는지도 기록

## 8. GitHub와 TIL 기록
- **Git** : 코드 변경 이력을 관리하는 버전 관리 도구
- **GitHub** : Git 저장소를 공유하고 협업하는 플랫폼
- **TIL(Today I Learned)** : 학습한 개념과 적용 결과를 정리하는 기록
- 개념 → 적용 → 검증 → 기록의 흐름으로 학습 내용을 관리

## 9. 핵심 정리
- Flutter는 Dart를 이용하여 여러 플랫폼을 대상으로 앱을 개발하는 프레임워크
- 앱 개발은 단순 코딩이 아니라 설계·검증·기록을 포함하는 과정
- AI의 제안은 참고 자료이며 실제 코드와 실행 결과로 검증해야 함
- 스스로 설명할 수 있는 결과물과 꾸준한 학습 기록을 만드는 것이 목표
