# 앱프로그래밍 6주차 배운 내용 정리

## 1. 동시성과 병렬성
- **동시성(Concurrency)** : 여러 작업의 진행 기간이 겹치도록 관리하는 성질
- **병렬성(Parallelism)** : 여러 작업이 실제로 같은 순간에 실행되는 성질
- **이벤트 루프(Event Loop)** : 입력·타이머·비동기 완료 등의 이벤트를 순서대로 처리하는 구조
- **이벤트 큐(Event Queue)** : 처리할 이벤트가 대기하는 줄
- **마이크로태스크 큐(Microtask Queue)** : 일반 이벤트보다 우선 처리되는 후속 작업의 큐
- 비동기 코드를 쓴다는 사실만으로 여러 CPU 작업이 병렬로 실행되는 것은 아님

## 2. 동기 처리와 비동기 처리
- **동기 처리** : 현재 작업이 끝나야 다음 처리를 진행하는 방식
- **비동기 처리** : 결과를 기다리는 동안 다른 이벤트를 처리할 수 있는 방식
- 서버 응답이나 파일 읽기처럼 기다림이 있는 작업은 `Future`와 `await`로 다룰 수 있음
- CPU를 오래 점유하는 계산은 단순히 `async`로 감싼다고 UI 멈춤이 해결되지 않음

## 3. Future와 async / await
- **Future<T>** : 나중에 값 또는 오류로 한 번 완료되는 비동기 결과
- **async** : 함수에서 `Future` 기반 비동기 처리를 사용할 수 있도록 선언
- **await** : `Future`가 완료될 때까지 해당 비동기 함수의 후속 처리를 기다림
- **try-catch** : 비동기 처리 중 발생한 오류를 받아 처리

```dart
Future<String> fetchNotice() async {
  await Future<void>.delayed(const Duration(seconds: 1));
  return '공지 자료를 읽었습니다.';
}
```

- `await`는 현재 isolate의 다른 이벤트 처리까지 모두 멈추는 명령이 아님

## 4. 비동기 요청의 화면 상태
- **idle** : 요청 전 대기 상태
- **loading** : 요청 결과를 기다리는 상태
- **success** : 결과를 정상적으로 받은 상태
- **failure** : 오류 안내나 복구 방법을 보여 주는 상태
- 화면은 현재 상태에 맞춰 진행 표시·결과·오류 메시지를 구분해야 함
- `setState()`는 상태 변경 후 Flutter에 화면 갱신을 알리는 메서드
- **mounted** : 비동기 작업이 끝난 후에도 현재 `State`가 위젯 트리에 연결되어 있는지 확인하는 값

## 5. FutureBuilder
- `FutureBuilder` : `Future`의 진행 상태에 따라 서로 다른 UI를 만드는 Widget
- **snapshot** : 연결된 비동기 작업의 현재 데이터·오류·상태를 담는 객체
- `ConnectionState.waiting`에서는 로딩 화면, `snapshot.hasError`에서는 오류 화면, 완료 시에는 데이터 화면을 표시
- `build()`가 반복될 때마다 새 요청이 시작되지 않도록 `Future`는 보통 `initState()` 등에서 미리 준비

## 6. Stream과 이벤트 처리
- **Stream<T>** : 시간에 따라 여러 값이나 오류를 전달하는 비동기 흐름
- **Future** : 한 번 완료되는 결과 / **Stream** : 여러 번 전달되는 이벤트
- **async*** : 여러 이벤트를 전달하는 Stream 함수를 선언
- **yield** : Stream에 값을 하나씩 전달
- **await for** : Stream의 이벤트를 기다리면서 순서대로 처리

```dart
Stream<int> counts() async* {
  for (var i = 1; i <= 3; i++) {
    await Future<void>.delayed(const Duration(milliseconds: 100));
    yield i;
  }
}
```

## 7. Stream 구독과 StreamController
- **listen()** : Stream 이벤트를 받아 처리하는 구독 연결
- **단일 구독 Stream** : 하나의 구독만 허용하는 Stream
- **broadcast Stream** : 여러 구독자가 같은 Stream을 구독할 수 있는 방식. 이전 이벤트를 새 구독자에게 자동 재전달하지 않음
- **StreamController** : Stream에 데이터·오류·완료 이벤트를 전달하는 객체
  - `sink.add()` : 새 값 전달
  - `addError()` : 오류 이벤트 전달
  - `close()` : 자신이 만든 StreamController의 흐름을 닫음
- 구독은 `cancel()`로 취소하며, 기존 구독의 `pause()`와 `resume()`은 새 구독을 만드는 동작과 다름

## 8. StreamBuilder와 자원 정리
- **StreamBuilder** : Stream 이벤트가 도착할 때마다 현재 값에 맞춰 화면을 구성하는 Widget
- 값 생성 → Stream 전달 → `listen()` 또는 `StreamBuilder`에서 관찰 → 구독·컨트롤러 정리
- 화면이 사라질 때 직접 관리한 구독이나 컨트롤러는 `dispose()`에서 정리하여 불필요한 작업을 방지

## 9. isolate와 무거운 계산
- **isolate** : 고유 메모리와 이벤트 루프를 가진 Dart 실행 단위
- **메인 isolate** : UI와 이벤트 처리에 관여하는 실행 단위
- **메시지 전달** : isolate끼리 메모리를 직접 공유하는 대신 메시지로 결과를 주고받는 방식
- **compute()** : 입력을 받아 계산하고 `Future`로 결과를 돌려주는 Flutter 함수
- **Isolate.run()** : 네이티브 환경에서 한 번의 계산을 별도 isolate에서 실행할 때 사용
- **Isolate.spawn()** : 오래 실행되는 작업자 isolate를 만들 때 사용
- 장기 작업자는 `SendPort`, `ReceivePort` 등을 이용해 메시지를 주고받고 종료를 관리
- 짧은 계산은 메인 isolate에서 처리하고, 큰 계산은 실행 시간과 환경을 확인해 분리를 검토
- 웹에서는 네이티브와 isolate 실행 방식이 다르므로 플랫폼 지원 여부를 먼저 확인

## 10. 프롬프트 엔지니어링
- **프롬프트 엔지니어링** : AI 요청을 설계하고 응답을 기준에 따라 평가하는 과정
- **역할** : AI가 어떤 관점에서 작업할지 설명
- **작업** : AI에게 맡길 내용을 명확하게 지정
- **입력** : 작업에 필요한 코드나 자료 제공
- **제약** : 수정할 범위와 유지해야 할 조건 지정
- **출력 형식** : 답변의 항목과 순서 지정
- **few-shot** : 기대하는 입력과 출력의 예시를 제공하는 방식
- **인수 조건(AC)** : 완료 여부를 관찰 가능한 행동으로 판단하는 기준

## 11. 컨텍스트 엔지니어링과 도구 계약
- **컨텍스트 엔지니어링** : AI가 참고할 자료, 사용할 도구와 실행 결과를 선택·관리하는 과정
- **도구 계약** : 도구의 목적, 입력, 출력, 오류, 권한, 부작용과 실행 범위를 정하는 약속
- **입력 계약** : 실행에 필요한 경로·인자·사전 조건
- **권한** : 도구가 허용받은 행동의 범위
- **부작용** : 실행으로 변경되는 파일이나 환경
- **오류 피드백** : 실제 실패를 다음 수정에 활용할 수 있도록 전달하는 정보
- 실행 전·후 확인한 사실과 미검증 내용을 구분해야 함

## 12. AI 협업 요청과 검증
- 현재 코드, 수정 범위, 인수 조건, 실행 환경을 동일하게 준비하여 요청을 비교
- 막연한 요청보다 **역할·작업·입력·제약·출력**을 구체적으로 적은 요청이 검증하기 편리함
- **제안** : AI가 수정 방법을 설명한 상태
- **실행 증거** : 분석 로그, 종료 코드, 실제 화면 등 확인한 자료
- **미검증** : 아직 실행하거나 관찰하지 않아 성공 여부를 판단할 수 없는 상태
- `flutter analyze`와 실제 화면 동작은 서로 다른 검증이므로 둘 다 확인
- 실패 시에는 기대 행동·실제 관찰·현재 코드·증거를 함께 전달하여 수정 요청

## 13. 핵심 정리
- `Future`는 한 번의 비동기 결과, `Stream`은 여러 번 전달되는 이벤트에 사용
- 비동기 처리는 기다리는 작업에 효과적이지만 무거운 계산의 병렬 실행을 뜻하지는 않음
- 네이티브 환경에서 긴 계산은 `isolate`와 `compute` 등의 사용을 검토
- `FutureBuilder`와 `StreamBuilder`로 데이터의 진행 상태를 화면에 반영
- 비동기 완료 후 `mounted` 확인과 구독·컨트롤러 정리로 화면 생명주기를 관리
- AI 협업에서는 명확한 요구, 도구의 범위, 인수 조건 및 실제 실행 증거가 중요
