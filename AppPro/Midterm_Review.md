## 2. 반드시 구분할 개념
- **Verification** : 요구대로 만들었는가 / **Validation** : 필요한 것을 만들었는가
- **StatelessWidget** : 자체 변경 상태를 관리하지 않음 / **StatefulWidget** : `State`와 함께 변경 상태 관리
- **Hot Reload** : 가급적 상태 유지하며 코드 반영 / **Hot Restart** : Dart 앱 상태를 초기화하고 재실행
- **Future vs Stream** : 한 번 완료되는 결과 vs 여러 번 도착하는 이벤트
- **비동기 vs 병렬** : 기다리는 동안 다른 작업을 진행하는 것과 실제 계산을 동시에 실행하는 것은 다름
- **프롬프트 엔지니어링** : 요청 지시 방법 / **컨텍스트 엔지니어링** : 참고할 코드·문서·도구·실행 결과를 구성·갱신

## 3. 코드 흐름과 인수 조건
```dart
setState(() {
  _done[index] = !_done[index];
});
```
- `_done = [false, false]`에서 완료·취소를 순서대로 하면 미완료 개수는 **2 → 1 → 2**.
- `await`는 해당 비동기 함수의 다음 실행을 기다리지만 앱의 모든 이벤트 처리를 막지는 않음.
- 학습한 출력 순서 예시에서 **A → C → B**가 되는 이유는 비동기 작업의 완료를 기다리는 순서 때문.
- **빈 제목 제출**: '제목을 입력하세요'와 같은 안내를 표시하고, **목록은 변경하지 않는 것**이 인수 조건.
- **MVP 예시**: 공부 항목 추가·목록 표시·완료 토글을 우선 구현하고 로그인·서버 저장 같은 부가 기능은 제외.
