# 앱프로그래밍기초 7주차 배운 내용 정리

## 1. 개인 앱 기획과 문제 정의
- **문제** : 실제 사용자가 해결하고 싶은 불편이나 요구
- **사용자** : 앱의 기능을 사용할 구체적인 대상
- **사용 상황** : 사용자가 언제, 어디서, 무엇을 하려는지 설명
- 앱에 넣을 기술보다 사용자의 실제 문제와 행동을 먼저 정의하는 것이 중요

## 2. 앱 기획의 기본 흐름
1. 문제와 사용자 정의
2. 해결하려는 핵심 기능과 가치 선정
3. 구현 가능한 범위 확인
4. 필요한 자료와 환경 선택
5. 인수 조건 작성 및 검증

## 3. 사용자 스토리
- **사용자 스토리(User Story)** : 사용자 관점에서 필요한 기능과 목적을 설명하는 문장
- 보통 **누가 / 무엇을 / 왜**의 구조로 정리
- 기능 이름만 적기보다 사용자가 얻을 결과를 명확히 해야 함

## 4. MVP(Minimum Viable Product)
- **MVP** : 사용자의 핵심 문제를 검증할 수 있는 최소한의 기능을 가진 제품
- 처음부터 부가 기능을 모두 개발하지 않고 필수 행동에 집중
- 범위를 지나치게 넓히면 구현과 검증이 어려워질 수 있음
- 핵심 기능과 추후 기능을 구분하여 우선순위 설정

## 5. 기능의 우선순위와 범위
- **필수 기능** : 핵심 사용자 경험을 성립시키는 동작
- **보류 기능** : 현재 단계에서 없어도 되는 추가 기능
- **제외 기능** : 이번 구현 범위에 포함하지 않을 기능
- 구현에 필요한 시간·환경·자료를 고려하여 범위를 결정

## 6. 인수 조건(AC)
- **Acceptance Criteria** : 기능이 올바르게 구현되었는지 관찰 가능한 행동으로 확인하는 기준
- 입력 상황과 기대 결과를 구체적으로 작성
- 예시 : 공부 항목 추가, 목록 표시, 완료 표시 전환, 완료된 항목 구분
- 정상 상황뿐 아니라 잘못된 입력과 경계 조건도 검토

## 7. 화면과 데이터 모델 연결
- **데이터 모델** : 화면에 표시하거나 변경해야 하는 정보를 표현하는 구조
- 예시 : 공부 항목의 ID, 제목, 완료 여부
- **화면(UI)** : 사용자가 정보를 보고 입력하는 영역
- **상태(State)** : 현재 화면과 데이터가 보여 주는 변경 가능한 값
- 입력 → 상태 변경 → 화면 갱신의 흐름으로 기능을 이해

## 8. 설계 결정 기록(ADR)
- **ADR(Architecture Decision Record)** : 선택한 설계 방법과 그 이유를 간단히 기록
- **상황** : 어떤 문제가 있었는지
- **선택지** : 어떤 방법들을 검토했는지
- **결정** : 무엇을 선택했는지
- **영향** : 이후 구현이나 변경에 어떤 영향을 주는지

## 9. 개발 규칙과 코드 품질
- **camelCase** 등 프로젝트의 일관된 명명 규칙 준수
- 한 번에 너무 많은 기능을 구현하지 않고 작은 작업으로 나누기
- `flutter analyze`와 실제 실행을 함께 사용하여 확인
- 현재 코드의 변경 전후 차이와 오류 발생 원인을 기록

## 10. 프롬프트와 컨텍스트 엔지니어링
- **프롬프트 엔지니어링** : AI에게 목표와 조건, 기대 출력 형식을 명확하게 전달
- **컨텍스트 엔지니어링** : 작업에 필요한 코드·문서·도구·검증 결과를 선택하여 제공
- 요청에 필요한 정보만 우선 제공하고 새로 확인한 오류나 결과에 따라 갱신
- 너무 많은 관련 없는 자료를 한꺼번에 전달하지 않도록 주의

## 11. 자료의 출처와 최신성
- **출처** : 자료를 어디에서 얻었는지 확인
- **최신성** : 현재 코드와 요구사항에 맞는 자료인지 확인
- **중복·충돌** : 오래된 문서와 새로운 변경 사항이 서로 어긋나는지 확인
- 개인 데이터·비밀번호 등 민감한 정보는 AI나 외부 도구에 불필요하게 전달하지 않음

## 12. AI 협업과 검증 순환
1. 요구사항과 현재 상태 정리
2. 필요한 범위에 한정하여 수정 요청
3. AI의 제안과 실제 변경 내용 확인
4. 실행·분석·화면 동작으로 검증
5. 오류나 미확인 사항을 반영하여 다음 요청 수정
- **제안 / 실행 / 검증**을 구분하고 실제 확인하지 않은 성공을 기록하지 않음

## 13. 핵심 정리
- 기능을 만들기 전에 사용자와 해결할 문제를 먼저 정의
- MVP를 통해 꼭 필요한 기능만 우선 구현
- 사용자 스토리, 인수 조건, 설계 결정 기록으로 기획과 구현을 연결
- AI 협업에서는 필요한 컨텍스트만 선택하고 실행 결과로 검증하는 습관이 중요
